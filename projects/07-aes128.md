# 07 · AES-128 encryption core

**Tier:** ⭐⭐⭐ Advanced · **full semester**

A crypto core is a great way to show a disciplined datapath, a published golden vector set to
check against, and a real area/throughput trade-off to analyse.

## Problem statement
Design an AES-128 encryption core implementing the four round transforms (SubBytes, ShiftRows,
MixColumns, AddRoundKey) and the key expansion, verified against the FIPS-197 test vectors.

## Module breakdown
- `sbox` — the 256-byte substitution (ROM, or computed GF(2⁸) inverse + affine for extra marks).
- `mix_columns` — GF(2⁸) matrix multiply (xtime).
- `key_expand` — generate the 11 round keys from the 128-bit cipher key.
- `aes_core` — iterative FSM: 10 rounds, last round skips MixColumns.

## Architecture choice (document it!)
- **Iterative** (one round/clock, ~11 cycles/block) — small area, modest throughput.
- **Unrolled/pipelined** (one block/clock after fill) — large area, high throughput.
Pick one, justify it, and estimate the other for your report.

## Verification plan
- The FIPS-197 Appendix B worked example (key `2b7e...`, plaintext `3243f6a8...`): check the
  ciphertext **and** the intermediate round states.
- The Appendix C-1 AES-128 vector.
- A batch of (key, plaintext, ciphertext) triples from a Python `pycryptodome` golden model.

## Stretch goals
- Add the decryption path (InvSubBytes/InvShiftRows/InvMixColumns).
- CBC mode wrapper (XOR with previous ciphertext / IV).
- Side-channel note: why a ROM S-box leaks timing-independently but still has power concerns.

## Deliverables
Spec, datapath diagram, FIPS-197 vector testbench (with intermediate-state checks), Python golden
model, synthesis report with area + cycles/block + estimated throughput, architecture-choice
justification.
